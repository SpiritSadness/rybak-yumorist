# План улучшений бота "Рыбак Юморист"

## Проблемы текущей версии

1. **Нет журналирования** - все логи только в консоль, нет записи в файл для отладки
2. **Нет обработки дубликатов в топе** - один анекдот может показываться несколько раз в топе
3. **Нет статистики** - бот не собирает данные о работе (сколько отправлено, сколько лайков)
4. **Ручной перезапуск** - при краше нужно вручную перезапускать
5. **Нет валидации данных** - плохие анекдоты могут попадать в БД
6. **Нет graceful shutdown** - при выключении данные могут теряться
7. **Монолитный код** - всё в одном файле, сложно поддерживать
8. **Нет обработки rate limits** - Telegram может банить за частые запросы

---

## План улучшений по приоритетам

### 🔴 Высокий приоритет (критично для стабильности)

#### 1. Логирование в файл
- Создать модуль `utils/logger.js`
- Записывать все действия бота в `logs/bot.log`
- Логировать ошибки отдельно в `logs/error.log`
- Добавить ротацию логов (по дням)

#### 2. Graceful shutdown
- Сохранять состояние при выключении
- Корректно закрывать соединения
- Перехватывать `SIGINT`, `SIGTERM`

#### 3. Авторебой при краше
- Добавить `pm2` для продакшена
- Или простой рестарт через `setTimeout` при краше

---

### 🟡 Средний приоритет (улучшает UX)

#### 4. Статистика бота
- Счётчик отправленных анекдотов
- Счётчик лайков/дизлайков
- Дата последней активности
- Сохранять в `data/stats.json`

#### 5. Исключить повторы в топе
- Анекдот дня не показывается в топ 5
- Топ 5 не содержит дубликатов
- Антитоп не пересекается с топ 5

#### 6. Улучшить обработку ошибок
- Показывать пользователю "Бот временно недоступен"
- Логировать причину ошибки с стектрейсом

---

### 🟢 Низкий приоритет (для профессионализма)

#### 7. Команда /stats - показать статистику бота
#### 8. Команда /ping - проверка работоспособности
#### 9. Webhook mode - вместо polling для продакшена
#### 10. Метрики Prometheus - для мониторинга

---

## Рекомендуемый порядок реализации

1. **Логирование** - сразу видно проблемы в файле
2. **Graceful shutdown** - защита от потери данных
3. **Обработка ошибок** - меньше крашей
4. **Статистика** - понимание работы бота
5. **Исключить повторы** - улучшает UX
6. **Команды /stats, /ping** - удобство администрирования
